## 2. 总体架构

采用**分层 + 响应式**架构，单向数据流，UI 随状态自动刷新：

```
┌──────────────────────────────────────────────┐
│  表现层 UI (screens / widgets / theme)          │  毛玻璃组件，ConsumerWidget
│   ↑ watch            ↓ 调用 notifier            │
├──────────────────────────────────────────────┤
│  状态层 (providers, Riverpod)                   │  AppNotifier 持有内存数据 AppData
│   - appProvider / converterProvider             │  派生 statsEngineProvider 等
├──────────────────────────────────────────────┤
│  业务层 (services)                              │  StatsEngine 统计、CurrencyConverter
│                                                 │  NotificationService、SyncService
├──────────────────────────────────────────────┤
│  数据层 (data / models)                         │  LocalStore(Hive) + SeedData
│                                                 │  Category / Platform / Subscription
└──────────────────────────────────────────────┘
            ↕ 可选                ↕
        Supabase 云端          设备本地 Hive
```

**数据流**：用户在 UI 操作 → 调 `AppNotifier` 方法 → 写本地(Hive) + 推云端 + 重排提醒 → 更新内存 `AppData` → Riverpod 通知所有 `watch` 的 Widget → 统计与图表**实时重算刷新**。

## 3. 技术选型与理由

| 关注点 | 选型 | 理由 |
|---|---|---|
| 跨端框架 | **Flutter** | 一套 Dart 代码原生编译到安卓+Windows（及其余端），性能高、毛玻璃(`BackdropFilter`)流畅、长期可维护 |
| 状态管理 | **Riverpod** | 编译期安全、响应式；改数值统计即时刷新；易测试 |
| 本地存储 | **Hive** | 纯 Dart、全平台通用、无原生依赖坑；以 JSON 字符串存实体，免代码生成 |
| 图表 | **fl_chart** | 柱状/环形，定制度高 |
| 到期提醒 | **flutter_local_notifications + timezone** | 跨端本地通知 |
| 云同步 | **Supabase** | 基于 HTTP，桌面/网页通用，规避 Firebase 桌面端短板 |
| 货币/日期 | **intl** | 本地化数字与日期格式化 |

> 关键取舍：以**本地优先**保证离线可用与隐私；云同步为可选增强。统计采用**内存计算**（数据量小，平台×订阅≈百级），换取实现简单与实时性。

## 4. 数据模型设计

三层实体 + 全局设置。每个实体含 `updatedAt` 与 `deleted`（软删除），为同步与合并预留。

### 4.1 Category 分类（`models/category.dart`）
`id, name, emoji, colorValue(ARGB), sortOrder, updatedAt, deleted`

### 4.2 Platform 平台（`models/platform.dart`）
`id, categoryId, name, emoji, notes, updatedAt, deleted` —— 一个平台可挂多条订阅记录。

### 4.3 Subscription 订阅期（`models/subscription.dart`）—— 核心
| 字段 | 说明 |
|---|---|
| `platformId` | 所属平台 |
| `cycle` | 月付/季付/年付（`BillingCycle`，含 `months`=1/3/12）|
| `amount` | **原始币种**金额（单周期价格）|
| `currency` | CNY / USD（`Currency`）|
| `startDate` / `endDate` | 订阅期起止，决定覆盖哪些自然月 |
| `autoRenew` | 自动续费（到期提醒用）|
| `notes`, `updatedAt`, `deleted` | |

> 关键设计：金额按**原始币种原值**保存，统计时再折算 CNY；同一平台「非连续订阅」用多条记录表达，互不影响。

### 4.4 AppSettings 设置（`models/app_settings.dart`）
`usdToCny(默认7.20), supabaseUrl/anonKey/syncEnabled, amortized(平摊视图,默认true), reminderEnabled(默认true), reminderLeadDays(默认3)`

### 4.5 存储方式（`data/local_store.dart`）
- 四个 Hive Box：`categories / platforms / subscriptions / meta`；实体以 `jsonEncode` 存为字符串，key=id。
- 首次启动按 `meta.seeded` 标志写入预置数据（`data/seed_data.dart`：**11 分类 + 38 平台**）。

## 5. 核心算法：时间线分摊统计（`services/stats_engine.dart`）

这是产品的核心价值，保证月/季/年三口径自洽。

**折算月均**：`月均成本(CNY) = 折算后金额 ÷ 周期月数`（月付÷1、季付÷3、年付÷12）。

**覆盖月份**：`coveredMonths(s)` 列出订阅期 `[start, end]` 覆盖的全部自然月（`YearMonth`）。

**逐级汇总**：
- `totalForMonth(subs, y, m)` = 当月所有在订记录的月均之和；
- `totalForQuarter` = 季内 3 个月之和；
- `totalForYear` = 12 个月之和；
- `monthlySeries` = 12 个月序列（柱状图）；
- `categoryBreakdownForMonth/Year` = 各分类占比（环形图）。

**货币折算**（`services/currency_service.dart`）：`CurrencyConverter(usdToCny)` 提供 `toCny`、`cnyToUsd`、`usdToCnyAmount`，供统计与双框联动复用。

**正确性**：`test/stats_engine_test.dart` 覆盖年付平摊、月付区间、季度合计、美元折算等，`flutter test` 可验证。

## 7. UI / UX 设计

- **视觉**：深空渐变背景 + 漂浮光斑 + 半透明磨砂卡片（`GlassCard`：`BackdropFilter` 高斯模糊 + 细描边 + 渐变）。深色主题，各分类主题色点缀。
- **首页自适应**（`LayoutBuilder`）：宽≥900（Windows/平板）→ **双栏仪表盘**（左：年份+统计+柱状图+即将到期；右：占比+分类清单）；窄屏（手机）→ **单列**。
- **实时反馈**：统计卡数值用 `TweenAnimationBuilder` 滚动到新值；统计卡标注当前「本月·X月 / 本季度·Q几」。
- **月度查看**：柱状图可**点选月份**，高亮该月并显示金额（含触摸 tooltip）。
- **配置入口**：首页分类清单带 `›` 与提示「点击可管理/配置每个 App」→ 进分类详情 → 「添加订阅」打开配置界面。
- **双币种联动**：`CurrencyDualInput` 填一框，另一框按固定汇率即时更新，高亮"主框"决定存储币种。

## 8. 跨平台构建设计

- **安卓**：`android/app/build.gradle.kts` 已开启 **core library desugaring**（`flutter_local_notifications` 需要）并启用 multiDex；`android/gradle.properties` 关闭 Kotlin 增量编译以规避跨磁盘缓存告警。这两个文件**已纳入版本控制**（其余 `android/` 由 `flutter create .` 本机生成、`.gitignore` 忽略）。
- **Windows**：需安装 Visual Studio（C++ 桌面工作负载）；`flutter build windows --release`。
- **网页（可选）**：`supabase_flutter` 在 web 需在 `web/index.html` 引入 Passkeys `bundle.js`；安卓/Windows 不需要。
- 仓库为"源码优先"：只跟踪 `lib/ pubspec.yaml test/` 及少量必要的安卓配置，平台脚手架本机 `flutter create .` 生成。

## 9. 云同步设计（Supabase）

- **本地优先**：所有改动先落 Hive，再 `upsert` 推送；失败静默，联网后下次再补。
- **拉取合并**：启动按 `updatedAt` 做 last-write-wins 合并（字段级合并为后续增强）。
- **配置**：设置页填 `URL/anonKey` 并开启；多端同账号互通。云端建表 SQL 见《安装说明书》。
- **当前进度**：服务骨架(`sync_service.dart`)与配置入口已就绪；多用户 Auth 隔离与实时订阅为后续里程碑。

---

## 10. 到期提醒设计（`notification_service.dart`）

- 在订阅期 `endDate` 前 `reminderLeadDays`（1/3/7/14 可选）天的上午 10:00 触发本地通知。
- 采用 `inexactAllowWhileIdle` 排程，**免安卓精确闹钟权限**；iOS/macOS 首次请求授权；不支持的平台静默跳过。
- 新增/改/删订阅、改设置、App 启动时，自动 `rescheduleAll` 重排。
- 首页「即将到期」列出未来 30 天到期项，临近(≤lead)标红。

## 14. 已知约束与风险

| 项 | 说明 / 应对 |
|---|---|
| 依赖版本固定 | pubspec 钉较旧版以保证当前稳定；升级用 `flutter pub upgrade --major-versions` 并回归测试 |
| 跨磁盘缓存告警 | 项目与 Pub 缓存不同盘时 Kotlin 增量缓存刷红，已用 `kotlin.incremental=false` 规避（不影响产物）|
| 安卓平台目录本机生成 | `android/` 多由本机 `flutter create` 生成；仅关键配置文件入库，换机需重跑 create |
| Web 端 supabase 限制 | 需手动加 `bundle.js`；非主目标端 |
| 同步冲突策略 | 当前 last-write-wins，重度多端并发编辑可能覆盖；M8 增强 |

## 15. 维护建议

- 改数据模型时同步更新 `toJson/fromJson` 与（如启用）云端表结构。
- 新增统计口径优先放进 `StatsEngine` 并补单测，保持 UI 薄、逻辑可测。
- UI 复用 `GlassCard` 与主题色常量，保持视觉一致。
- 提交遵循清晰中文 commit；功能在指定分支开发后推送。
