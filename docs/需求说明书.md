## 1. 项目背景与目标

你同时开通了大量平台的 VIP / 会员 / 订阅服务（电商、音乐、视频、AI 大模型、云盘、出行、VPN 等），存在以下痛点：

- 平台太多太杂，记不清每月/每年到底花了多少钱；
- 有的会员只订其中某几个月，并非全年连续，难以统计；
- 月付、季付、年付混在一起，无法横向比较真实月度成本；
- 缺少一个**手机、电脑都能打开**、界面美观、统计自动实时更新的工具。

**目标**：做一款**本地优先、跨平台（手机 + 电脑）**的订阅记账软件，核心是「**以时间线为根本**」自动统计每月 / 每季度 / 每年的会员支出，界面采用毛玻璃特效，数值修改后统计实时刷新。

## 3. 核心概念与数据模型

为了正确处理「某平台只订其中某几个月、不是全年连续」的情况，我们把数据拆成三层：

### 3.1 分类（Category）
- 字段：名称、图标 / Emoji、颜色、排序。

### 3.2 平台（Platform）
- 字段：名称、所属分类、Logo / 图标、备注。
- 一个平台下可以有**多条订阅记录**（不同时间段、不同周期）。

### 3.3 订阅记录 / 订阅期（Subscription Term）—— 最关键
代表「某平台的一段订阅」，字段：

| 字段 | 说明 |
|---|---|
| 所属平台 | 关联 Platform |
| 计费周期 cycle | 月付 / 季付 / 年付（枚举）|
| 金额 amount | 该周期的**单次价格**（如月付 ¥15、年付 ¥168）|
| 起始日期 startDate | 该订阅期开始日 |
| 结束日期 endDate | 该订阅期结束日 |
| 货币 currency | 默认 CNY，预留多币种 |
| 是否自动续费 autoRenew | 布尔，用于到期提醒 |
| 备注 notes | 可选 |

> 这样设计的好处：同一个平台「3 月单独买了 1 个月、9 月又买了半年」可以用两条互不影响的订阅记录表达，统计自然正确。

## 4. 核心算法：以时间线为根本的统计

这是你最看重的部分。规则定义如下，**保证月 / 季 / 年三个口径完全自洽**：

### 4.1 折算原则
- 定义每条订阅记录的「**月均成本** monthlyEquivalent = 金额 ÷ 周期月数」：
  - 月付：周期月数 = 1 → 月均 = 金额本身；
  - 季付：周期月数 = 3 → 月均 = 金额 ÷ 3；
  - 年付：周期月数 = 12 → 月均 = 金额 ÷ 12。
- 把「月均成本」**分摊到该订阅期 [startDate, endDate] 覆盖的每一个自然月**。

### 4.2 三级汇总（时间线驱动）
- **月度统计**：某个月的总支出 = 当月所有「在订阅期内的记录」的月均成本之和；
- **季度统计**：某季度总支出 = 该季度 3 个自然月的月度统计之和；
- **年度统计**：某年总支出 = 该年 12 个自然月的月度统计之和。

> 季付 / 年付既可以「平摊到每个月再汇总」，也可以直接落在对应季度 —— 由于上面的折算口径统一，两种视角结果一致，不会出现重复计算或对不上的情况。

### 4.3 示例
- 年付 ¥120，订阅期 2026-03 ~ 2027-02 → 每月计 ¥10；2026 年（3~12 月，共 10 个月）计入 ¥100，2027 年（1~2 月）计入 ¥20。
- 月付 ¥15，只订 2026-01 ~ 2026-03（3 个月）→ 1/2/3 月各 ¥15，Q1 合计 ¥45，全年 ¥45。
- 季付 ¥45，订阅期 2026-04 ~ 2026-06 → 4/5/6 月各 ¥15，Q2 合计 ¥45。

### 4.4 展示口径（两套并行，可切换）
1. **平摊视图（默认）**：年付/季付平摊到每月，适合横向比较「真实月成本」；
2. **实付视图（可选）**：按实际付款月一次性计入（如年付在付款当月显示全额），适合现金流视角。
> 出厂默认「平摊视图」，符合你描述的核心诉求。

## 5. 功能需求清单

### 5.1 必做（MVP / P0）
- [ ] **分类管理**：预置 11 类，支持增 / 删 / 改 / 排序、自定义图标与颜色。
- [ ] **平台管理**：在分类下增删平台，预置 38 个平台的图标。
- [ ] **订阅记录管理**：为平台添加订阅期，选择月/季/年付、填写金额与**起止日期**。
- [ ] **双币种联动输入（已确认）**：金额可填**人民币或美元**，二者按**固定汇率**联动——填人民币框，美元框自动更新；填美元框，人民币框自动更新。统计内部统一折算为本币（默认 CNY）。汇率值在设置中可调。
- [ ] **实时自动统计**：任意数值修改 → 月 / 季 / 年统计**立即刷新**（无需手动点计算）。
- [ ] **时间线总览**：按月/季/年三个口径查看总支出，可切换年份、季度。
- [ ] **分类支出占比**：饼图 / 条形图展示各分类、各平台花费占比。
- [ ] **本地持久化**：数据存本地，离线可用，重启不丢。
- [ ] **云同步（已确认）**：手机与电脑**互通云同步**，本地优先 + 后台同步，离线可编辑、联网自动合并。技术上采用 Supabase（HTTP 接口，全平台含桌面/网页通用）。
- [ ] **毛玻璃 UI**：见第 7 节。
- [ ] **数据导入导出**：JSON / CSV 备份与恢复（防止设备更换丢数据）。

### 5.2 增强（P1）
- [ ] **到期提醒**：临近 endDate / 自动续费前本地通知。
- [ ] **多币种**：USD 等外币（ChatGPT、Claude、Cursor 等）按汇率折算成本币展示。
- [ ] **搜索与筛选**：按名称、分类、周期、金额区间筛选。
- [ ] **年度账单报告**：年末生成「我这一年订阅花了多少」可视化报告。
- [ ] **深浅色主题**。

### 5.3 远期（P2）
- [ ] **跨设备云同步**（手机 ↔ 电脑），可选自建（如 WebDAV / 私有云）或第三方。
- [ ] 账单邮件 / 截图自动识别录入（AI 辅助）。

## 6. 同类产品调研与可借鉴之处

调研了国内外主流订阅管理工具，结论与借鉴点如下：

| 产品 | 亮点 | 可借鉴到本项目 |
|---|---|---|
| **Bobby**（iOS） | 极简卡片列表 + 醒目「每月总额」，多币种自动按月/年汇总 | 首页大号「本月/本年总额」+ 卡片式分类列表 |
| **Billey / Billy**（iOS/Android） | 可视化图表看哪个软件花得多；可设周期、首付时间、是否自动续费 | 分类/平台占比图表、自动续费开关 |
| **效率控**（最贴近你的需求） | 周期支持**月/季/半年/年**，统计分「按月」与「按年」两个口径，内置国内外会员 | **多周期 + 多口径统计**正是你的核心诉求，直接对标 |
| **Onebox / 有数鸟（小程序）** | 对国内服务（网易云、知乎、微信读书等）支持好，到期提醒 | 国内平台图标库、到期提醒 |
| **Rocket Money / Monarch**（国外） | 银行自动识别订阅、账单协商、预算 | 远期「自动识别录入」思路（P2，本项目以隐私本地优先，不接银行）|
| **ReSubs / SenticMoney** | 隐私优先、本地存储、CSV 导入、续费提醒、多币种 | **本地优先 + 导入导出 + 多币种**的产品定位 |

**本项目差异化定位**：以**时间线分摊统计**为核心（年付/季付精确平摊到月，再逐级汇总），原生支持「非连续订阅期」，国内外平台通吃，毛玻璃美学，手机电脑同源。这一点比上述多数产品（多按「当前在订的固定周期」估算）更精确。

## 7. UI / 交互设计

- **风格**：毛玻璃拟态（Glassmorphism）—— 半透明磨砂卡片、柔和高斯模糊、细描边、深色渐变 / 星空背景，弱投影。
- **首页（星图总览）**：
  - 顶部大号数字卡：**本月总额 / 本季度总额 / 本年总额**（可一键切换口径）；
  - 中部：分类支出环形图 + 时间线柱状图（按月）；
  - 下部：分类卡片列表，点进去看平台与订阅记录。
- **录入交互**：选择周期（月/季/年分段控件）→ 填金额 → 选起止日期（日期选择器）→ 保存即时入账。
- **实时性**：采用响应式状态管理，任一数值变更触发统计重算并以动画过渡刷新。
- **适配**：手机竖屏单列；平板 / 电脑宽屏自适应为多列网格 + 侧边栏。

## 8. 技术选型（手机 + 电脑同源方案）

### 8.1 推荐方案：**Flutter 一套代码，多端原生编译**

| 维度 | 说明 |
|---|---|
| 覆盖端 | 同一套 Dart 代码 → **Android、iOS、Windows、macOS、Linux**（可选 Web/PWA），完美满足「手机是一个 App、电脑是一个软件」 |
| 性能 | 自带渲染引擎（Impeller / Skia），原生编译，60–120fps，动画与毛玻璃模糊（`BackdropFilter`）流畅 |
| 美观 | 对毛玻璃、渐变、图表支持极好，UI 高度可定制 |
| 稳定 & 工程化 | 成熟生态，Google 维护，长期可靠；适合个人长期维护 |
| 本地存储 | `drift`（SQLite，类型安全、响应式查询，数值变更自动驱动 UI 刷新）|
| 状态管理 | `Riverpod`（响应式，实现「改数值→统计实时更新」） |
| 图表 | `fl_chart`（环形 / 柱状 / 折线）|

**为什么不选其他**：
- 纯 Web/PWA：最省事但手机端「软件感」与离线体验略弱，毛玻璃模糊在部分浏览器性能差；
- React Native：移动强、桌面端（Windows/macOS）支持不如 Flutter 统一；
- Tauri/Electron：擅长桌面，移动端不原生。

> 结论：**Flutter** 在「跨手机+电脑、单一代码库、性能、稳定、毛玻璃美学、可长期维护」上综合最优。

### 8.2 电脑端「更轻」的备选
若你希望电脑端更轻量、零安装，可额外提供一个 **PWA（Web 版）**：浏览器打开即用、可「安装到桌面」，与 Flutter 共用同一数据模型（Flutter 也能编译 Web）。即「**Flutter 主攻手机 + 桌面原生，顺带产出 Web 版**」，一份代码三端覆盖。

### 8.3 数据与同步（已确认开启云同步）
- **本地优先**：所有数据先存设备本地（Hive / SQLite），离线完全可用；
- **云同步**：采用 **Supabase**（Postgres + Auth + Realtime，基于 HTTP，**全平台通用**，桌面/网页都能跑，避免 Firebase 在 Windows/Linux 桌面支持差的问题）。手机与电脑用同一账号登录即可互通，本地改动后台自动上行、远端变更下行合并；
- **冲突策略**：按记录「最后修改时间」合并（last-write-wins，字段级可后续增强）；
- **备份**：另提供一键导出 / 导入 JSON、CSV 作为兜底。

### 8.4 双币种联动汇率
- 订阅金额输入框为 **CNY / USD 双框联动**：内部存「原始金额 + 原始币种」，并按设置中的**固定汇率**实时换算另一币种显示；
- 统计时统一折算为本币（默认 CNY）= 原始金额 ×（必要时）汇率；
- 汇率默认值可在设置中修改（如 1 USD = 7.20 CNY）。

## 9. 非功能性需求
- **隐私**：纯本地，不上传，不接银行账户；
- **性能**：38+ 平台、上百条订阅记录下统计重算 < 50ms；
- **可靠**：本地数据库事务保证不丢数据，导出可恢复；
- **可维护**：清晰分层（数据层 / 业务层 / UI 层），单人可长期维护；
- **可扩展**：分类、平台、币种均可自定义增删。
